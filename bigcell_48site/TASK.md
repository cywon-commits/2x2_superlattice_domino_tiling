# 계산 의뢰서: 48·54사이트 주기셀로 자화 계단의 추가 단 찾기

의뢰자: 원창연 (경희대 물리학과) · 프로젝트: *Quantum order by disorder among lozenge tilings*
실행 대상: Claude Code 또는 팀원 워크스테이션/클러스터 (Linux, Python ≥ 3.10, 코어 8개 이상 권장)

---

## 1. 목적

S = ½ Heisenberg 반강자성체를 로젠지 타일링 위에 올렸을 때, T = 0 자화 계단은 지금까지 **36사이트 이하 주기셀**에서만 전수 탐색했습니다.
이번 계산의 질문은 하나입니다.

> **셀을 48·54사이트로 키우면 계단에 새 단(새 결정)이 생기는가? 기존 단의 결정 구조는 바뀌는가?**

현재 결과 (QMC, L = 36; 논문 Table I, `ref/`):

| 결정 | M/M_dice | δe (10⁻³ J) | 자기장 창 (J) |
|---|---|---|---|
| M/6 | 1/6 | −2.90(10) | 0.094–0.128 |
| M/3 | 1/3 | −4.57(13) | 0.128–0.168 |
| M/2 (허브 없음) | 1/2 | −5.11(10) | 0.168–0.212 |
| 2M/3 | 2/3 | −4.45(10) | 0.212–0.268 |

δe는 사각형형–dice를 잇는 직선에서 잰 영점 에너지 편차입니다.

## 2. 왜 48·54사이트인가

- **L = 36 토러스에 들어맞습니다.** 셀 변 p, q가 36의 약수이면, 기존 L = 36 QMC 프로토콜(β = 36, 1200 + 6000 sweep)을 그대로 쓸 수 있습니다. 기존 결과와 직접 비교되고, 더 큰 QMC도 필요 없습니다.
  - N = 48 셀: 12×4, 4×12
  - N = 54 셀: 18×3, 3×18, 9×6, 6×9
- **새 자화값이 생깁니다.** 예를 들어 M/M_dice = 1/8, 3/8, 5/8, 7/8, 4/9, 5/9 등입니다.
- **72사이트는 현재 알고리즘으로 불가능합니다.** 열거 시간이 12사이트마다 약 150배씩 늘어서, 셀 하나에 수십 일이 걸립니다(§7).

`scripts/cells_A.txt`에는 N ≤ 54이고 36×36 토러스에 맞는 셀 **79개**가 모두 들어 있습니다. N ≤ 36 셀도 새 방법으로 다시 열거합니다(§3 파일럿 참고).

## 3. 파일럿 결과 (의뢰 전에 확인한 것)

- **열거 코드 검증.** 새 numba 열거기 `enum_nb.py`의 타일링 수와 이분 타일링 수가 기존 `per_big.py` 결과와 정확히 일치합니다. 예: 9×4 s=0 → 326 273 / 23 344, 12×3 s=10 → 971 697 / 11 823.
- **48사이트 셀 하나(12×4, s=4)의 성능.** 1.32×10⁷ 타일링을 249 s에 처리했고, 구조 클래스는 12 641개였습니다.
- **LSWT 기준선 (정정됨).** 36사이트 이하 셀 63개를 새 방법으로 전부 다시 열거하고, 허브 없는 구조 4 510개의 Bloch LSWT를 계산했습니다. 그 결과 허브 없는 구간의 LSWT 껍질 꼭짓점은 **M/6, M/3, M/2**로 QMC 결정과 같습니다.
  - 초기 파일럿에서 "새 꼭짓점"으로 보였던 M/4, 3M/8은 옛 36사이트 기준표가 불완전해서 생긴 착시였습니다.
  - 완전한 기준선과 비교하면 48사이트 12×4(s=0, 4)의 M/4는 1.1×10⁻⁴ J, 3M/8은 6.5×10⁻⁵ J만큼 껍질 위에 있습니다.
- **36사이트에서도 기존 선택이 놓친 구조가 있었습니다.** 옛 방법은 모델 에너지(배위수 히스토그램에만 의존) 상위 K개만 남겼습니다. 새 방법은 구조 클래스마다 대표 하나씩을 남기므로, 단계 A는 N ≤ 36 셀도 다시 돌립니다(`cells_A.txt`에 포함).
- **유효 결함 격자기체 모형 (`ce/`).** z = 3, 5 결함(곡률 ±1)의 쌍 상호작용을 거리 √7까지 넣은 모형이 LSWT 에너지를 교차검증 rms 1.4×10⁻⁵ J로 재현합니다. 처음 보는 48사이트 구조에서도 rms 2.1×10⁻⁵ J입니다. 54사이트 결과가 나오면 `ce/ce_score.py`로 모든 클래스를 빠르게 점수 매겨, 단계 B의 모델 창에서 빠진 후보가 없는지 교차 확인합니다.
- **주의:** LSWT와 QMC는 결정 순서가 다를 수 있습니다(논문 Sec. V, M/3). **판정은 QMC로 합니다.**
- **기대치.** 48사이트에서는 새 단이 나오지 않을 가능성이 큽니다. 새 단이 있다면 54사이트의 4/9, 5/9 같은 값이나 M/2 위(허브 구간)일 가능성이 높습니다. 새 단이 없다는 결과도 그 자체로 논문의 한계 (a)항을 줄이는 결과입니다.

## 5. 실행 방법

```bash
pip install -r requirements.txt
bash scripts/run_all.sh 16          # 인자 = 병렬 코어 수. 모든 출력은 work/ 에 생성
```

단계별로 따로 돌릴 수도 있습니다(`work/`에서 실행).

| 단계 | 명령 | 내용 | 예상 시간 |
|---|---|---|---|
| A | `python ../code/enum_nb.py P Q S` | 셀 전수 열거, 구조 클래스별 대표 저장 → `cand_PxQ_sS.json` | N ≤ 36: 셀당 수 초. N = 48: 셀당 약 4분. N = 54: 셀당 20분 이상, 추정 1–2시간 (§8). 합계 약 15–25 CPU·h |
| B | `python ../code/rank_bloch.py cand_*.json` | m별 모델 에너지 창(tol 0.002 J, 최대 30개) → Bloch LSWT → 볼록 껍질·전이장 → `rank_result.json`, `rank_B.txt` | 수 CPU·h |
| C | `python ../code/make_qmc.py --top 2 --seeds 1,2` 후 `jobs_qmc.txt` 실행 | 껍질 꼭짓점마다 LSWT 상위 2개 구조 × 시드 2개로 L=36 QMC. 발표된 결정과 같은 구조는 자동으로 건너뜀 | 작업당 1–2시간 (코어 1개). 약 20–30개 작업 |
| B′ | `python ../ce/ce_score.py` | 모든 허브 없는 클래스를 CE 모형으로 점수 매겨, m별 최저 후보가 단계 B에 포함됐는지 확인 (`MISSING`이 있으면 `--tol`을 키워 B 재실행) | 수 분 |
| D | `python ../code/stair_update.py` | 기존 QMC와 새 QMC를 합쳐 계단 재구성, 부트스트랩 → `stair_new.json`, `stair_new.png`, `stair_D.txt` | 1분 |

- QMC는 `qmc_ckpt.py`가 90초마다 체크포인트를 남깁니다. 중단돼도 같은 명령을 다시 실행하면 이어서 돕니다(`run_all.sh`가 자동으로 반복).
- 스레드는 1로 고정하고(`run_all.sh`가 설정), 병렬화는 프로세스 수로 합니다.
- 추가로 확인하고 싶은 자화값이 있으면 C 단계에서 지정합니다. 예: `EXTRA=0.0417,0.0625 bash scripts/run_all.sh`. 값은 m이며, M/M_dice = 6m입니다.

## 6. 검증 체크리스트 (보고서에 포함)

1. **열거 재현.** `enum_log.jsonl`에서 9×4 s=0 → tilings 326273, bipartite 23344. 12×3 s=10 → 971697 / 11823.
2. **overflow.** 모든 셀에서 `overflow: false`여야 합니다. true이면 `--maxkeys`를 키워 다시 돌립니다.
3. **계단 재현.** 새 QMC 없이 D를 돌리면 전이장이 0.094, 0.128, 0.168, 0.212, 0.268 J로 나와야 합니다(파일럿에서 확인함).
4. **Lieb 섹터.** QMC 결과의 m이 해당 구조의 m_L과 0.002 이내여야 합니다. 벗어난 실행은 D가 자동으로 제외하고 경고를 출력합니다. 이 경우 h를 창의 아래쪽으로 낮춰 다시 돌립니다.
5. **시드 일치.** 두 시드의 δe가 2σ 이내여야 합니다.

## 8. 한계와 선택 과제

- **54사이트 시간은 추정치입니다.** 파일럿에서 9×6 s=3 한 셀이 20분 넘게 걸리고도 끝나지 않았습니다(코어 1개). 48 → 54의 증가율(타일링 수 약 7–12배, 막다른 가지 증가 포함)로 보면 셀당 1–2시간입니다. 12개 셀을 병렬로 돌리면 코어 12개에서 약 2시간입니다.
- **72사이트 이상(선택).** 현재 깊이 우선 열거로는 셀 하나에 수십 일이 걸립니다. 새 단이 48·54에서 발견될 때만, 전이행렬(transfer matrix)이나 띠별 동적 계획법으로 열거기를 다시 짜는 것을 검토합니다.
- **L = 36에 맞지 않는 셀(선택).** 8×6, 16×3, 5×9 같은 셀은 L = 48이나 45 토러스 QMC가 필요합니다. 이번 범위에서는 제외합니다.
- **LSWT 해상도.** 10⁻⁴ J 수준의 LSWT 순서는 QMC와 다를 수 있으므로, 후보는 LSWT로 고르되 판정은 QMC로 합니다.
- **M/3의 크기 의존성.** M/3는 L = 24와 36에서 값이 다릅니다(−3.8 vs −4.57). 새 M/3 구조가 나오면 L = 36에서만 비교하고, 그 점을 보고서에 적습니다.
